# audit 单题标准结构模板

本文件定义技术面试题的标准结构，确保每道题目都有明确的考察点、优秀回答标准、评分标准和追问方向。

---

## 单题标准格式

```markdown
### [题号]
**问题：** [题目文本]
**考察点：** [本题主要评估的能力]
**优秀回答要点：**
- 要点1：[具体表现]
- 要点2：[具体表现]
- 要点3：[具体表现]
**评分标准：**
- 5分：[优秀回答的判定锚点]
- 3分：[合格回答的判定锚点]
- 1分：[明显风险或不合格表现]
**追问：** [至少1个追问方向]
```

---

## 各字段说明

### 问题（必填）
- 简洁明了，一句话表达清楚
- 避免双重否定和歧义
- 线上面试时考虑口语表达是否清晰

### 考察点（必填）
- 明确本题主要评估哪个/哪些能力
- 建议从以下维度选择：
  - 基础知识准确性
  - 原理深度
  - 实战经验真实性
  - 架构设计能力
  - 排障与稳定性意识
  - 工程化能力
  - 沟通表达与逻辑
  - 决策与权衡能力
  - 岗位匹配度

### 优秀回答要点（必填，3-5条）
- 描述"好回答"的具体表现
- 区分"合格"和"优秀"的边界
- 避免过于笼统（如"回答正确"）
- 应该是可观察、可判断的行为或内容

### 评分标准（默认必填，3档即可）
- 默认使用 5分 / 3分 / 1分 三档锚点，便于快速判断
- 5分强调：真实项目、关键细节、trade-off、量化结果、追问下仍稳定
- 3分强调：基本正确、能说主线，但边界、数据或深度一般
- 1分强调：概念混淆、回答空泛、无法落到真实项目或关键细节失真
- 如果是整套题库，也可在题后补单题评分标准，在文末再补统一 rubric

### 追问（必填，至少1个）
- 用于验证"知道"与"做过"的区别
- 用于深挖细节或边界条件
- 用于检验举一反三能力
- 建议包含至少一个"项目实战类追问"

## 不同题型的推荐评分模板

### 项目深挖题
```markdown
**评分标准：**
- 5分：能结合真实项目讲清场景、关键设计、量化指标、取舍与结果，追问下仍稳定。
- 3分：能说清基本思路和主要措施，但数据、边界或个人贡献描述偏弱。
- 1分：回答空泛，难以落到真实经历，关键细节和指标说不清。
```

### 基础原理题
```markdown
**评分标准：**
- 5分：原理准确，能结合项目说明适用边界、常见坑和优化取舍。
- 3分：核心概念基本正确，但对底层机制或边界掌握一般。
- 1分：概念混淆或只能背结论，追问后明显失真。
```

### 架构设计题
```markdown
**评分标准：**
- 5分：方案完整，覆盖容量、一致性、稳定性、回滚，并能说明 trade-off。
- 3分：有基本可行方案，但边界条件和治理手段不足。
- 1分：主要堆技术名词，没有清晰链路和权衡。
```

### 排障 / 稳定性题
```markdown
**评分标准：**
- 5分：排查过程结构完整，包含止损、定位、修复、复盘闭环，并有真实案例支撑。
- 3分：能给出基本处理顺序，但缺少案例或闭环意识。
- 1分：主要靠猜测或“重启试试”，缺乏监控、回滚和复盘意识。
```

### 行为协作题
```markdown
**评分标准：**
- 5分：案例具体，能说明冲突、推动策略、结果和复盘，体现 ownership。
- 3分：能给出案例，但推动过程和个人作用不够清楚。
- 1分：回答空泛，只有态度没有行动证据。
```

## 题目类型与模板

### 类型1：概念理解题

```markdown
### [题号]
**问题：** 请解释 [概念名称]，它在实际项目中有什么作用？
**考察点：** 基础知识准确性 + 原理深度
**优秀回答要点：**
- 能准确定义概念，无明显错误
- 能说明底层原理或工作机制
- 能结合实际场景举例说明应用
- 能指出常见误区或边界条件
**评分标准：**
- 5分：原理准确，能结合项目说明适用边界、常见坑和优化取舍。
- 3分：核心概念基本正确，但对底层机制或边界掌握一般。
- 1分：概念混淆或只能背结论，追问后明显失真。
**追问：** 你在项目中遇到过这个概念相关的坑吗？怎么解决的？
```

### 类型2：项目经验题

```markdown
### [题号]
**问题：** 请介绍一下你在 [项目名称] 中负责的核心模块，以及你的主要贡献？
**考察点：** 实战经验真实性 + 贡献度
**优秀回答要点：**
- 能清晰描述项目背景和目标
- 能明确自己负责的模块边界
- 能说明关键决策和权衡过程
- 能给出量化结果或具体收益
- 能区分"参与"和"主导"
**评分标准：**
- 5分：能结合真实项目讲清场景、关键设计、量化指标、取舍与结果，追问下仍稳定。
- 3分：能说清基本思路和主要措施，但数据、边界或个人贡献描述偏弱。
- 1分：回答空泛，难以落到真实经历，关键细节和指标说不清。
**追问：** 如果把这个模块的代码拉出来给你，你最有把握讲清楚哪部分？
```

### 类型3：架构设计题

```markdown
### [题号]
**问题：** [场景描述]，你会如何设计这个系统？
**考察点：** 架构设计能力 + 权衡决策
**优秀回答要点：**
- 能从需求出发拆解问题
- 能提出多种可行方案并比较
- 能说明关键设计决策的理由
- 能考虑扩展性、稳定性、成本
- 能识别边界条件和风险点
**评分标准：**
- 5分：方案完整，覆盖容量、一致性、稳定性、回滚，并能说明 trade-off。
- 3分：有基本可行方案，但边界条件和治理手段不足。
- 1分：主要堆技术名词，没有清晰链路和权衡。
**追问：** 如果 [约束条件变化]，你的方案需要怎么调整？
```

### 类型4：排障场景题

```markdown
### [题号]
**问题：** 如果 [故障现象]，你会怎么排查？
**考察点：** 排障能力 + 稳定性意识
**优秀回答要点：**
- 有结构化的排查思路，不是"瞎猜"
- 能分层定位：网络/服务/数据库/应用
- 能说明需要查看的日志、指标、链路
- 能考虑止损和回滚方案
- 能提出预防复发的措施
**评分标准：**
- 5分：排查过程结构完整，包含止损、定位、修复、复盘闭环，并有真实案例支撑。
- 3分：能给出基本处理顺序，但缺少案例或闭环意识。
- 1分：主要靠猜测或“重启试试”，缺乏监控、回滚和复盘意识。
**追问：** 你遇到过类似的线上故障吗？当时是怎么处理的？
```

### 类型5：行为协作题

```markdown
### [题号]
**问题：** 请举一个你推动跨团队协作或解决技术争议的例子。
**考察点：** 沟通协作 + ownership
**优秀回答要点：**
- 有具体的案例背景和冲突点
- 能说明自己的推动策略和沟通方式
- 能描述最终达成的结果和影响
- 能复盘过程中的收获或教训
**评分标准：**
- 5分：案例具体，能说明冲突、推动策略、结果和复盘，体现 ownership。
- 3分：能给出案例，但推动过程和个人作用不够清楚。
- 1分：回答空泛，只有态度没有行动证据。
**追问：** 如果对方仍然不配合，你会怎么办？
```

### 类型6：代码/配置口述题（线上面试专用）

```markdown
### [题号]
**问题：** 线上问法：请口述 [功能/配置/流程] 的关键设计点，不要求写完整代码。
**考察点：** 设计能力 + 表达清晰度
**优秀回答要点：**
- 能说清核心结构和关键组件
- 能指出关键配置项和注意事项
- 能说明如何验证设计是否正确
- 能考虑边界条件和异常处理
**评分标准：**
- 5分：方案完整，表达清晰，能说明验证路径、边界条件和风险控制。
- 3分：主线正确，但关键配置、验证方式或异常场景覆盖不足。
- 1分：表达混乱，只会背命令或配置名词，无法形成完整方案。
**追问：** 如果这个功能需要支持 [更高并发/更大数据量]，你会怎么调整？
```

## 追问设计指南

### 四向追问法

对每个重点项目或深度问题，使用四个方向的追问：

| 方向 | 目的 | 示例追问 |
|------|------|----------|
| **向下** | 挖实现细节 | "这个模块内部是怎么实现的？" |
| **向外** | 挖边界与依赖 | "这个模块和其他模块是怎么交互的？" |
| **向后** | 挖效果与复盘 | "上线后效果如何？有什么可以改进的？" |
| **向前** | 挖选型理由 | "为什么选择这个方案而不是另一个？" |

### 真实性校验追问

用于区分"背过"和"做过"：

| 类型 | 示例追问 |
|------|----------|
| 量化追问 | "QPS是多少？数据量多大？延迟多少？" |
| 角色边界追问 | "你负责到哪一层？团队有多少人？" |
| 决策追问 | "这个方案是你定的吗？为什么选A不选B？" |
| 坑点追问 | "这个项目遇到过什么坑？怎么发现的？" |
| 代码追问 | "如果现在让你讲这段代码，你能讲到什么程度？" |

## 质量检查清单

生成题目后，检查每道题是否满足：

- [ ] 问题表述清晰，无歧义
- [ ] 考察点明确且与岗位相关
- [ ] 优秀回答要点有3-5条具体表现
- [ ] 已补单题评分标准（至少 5/3/1 三档）
- [ ] 至少有1个追问
- [ ] 追问能区分"知道"与"做过"
- [ ] 题目难度与目标级别匹配
- [ ] 适合线上面试的表达方式（如适用）
