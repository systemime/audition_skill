# audit 线上面试问法指南

本文件提供线上视频面试中技术问题的标准化问法，帮助面试官在不依赖现场环境的情况下有效考察候选人。

---

## 核心原则

线上面试与现场面试的最大区别：
- **无法现场运行代码**
- **无法查看候选人开发环境**
- **网络和设备可能影响体验**
- **注意力更容易分散**

因此，线上面试的问法需要调整：**从"写出完整代码"转向"口述思路和关键设计"**。

---

## 通用开场白

在涉及代码/配置/部署类问题前，建议先说明：

> "接下来这个问题涉及代码/配置，但我们不要求你现场跑通环境。请口述你的实现思路，如果能写出核心伪代码或关键函数签名更好。我更关心你的设计思路和边界考虑。"

---

## 标准化问法模板

### 1. 代码设计类问题

**标准问法：**
> "请你口述这个功能的实现思路，不要求写完整代码。如果可以的话，写出核心伪代码或关键函数签名即可。"

**可追加：**
> "请说明你会怎么验证这个实现是正确的。"

**示例：**
> "请口述一个任务提交+异步处理+状态查询的接口设计。不需要写完整代码，写出关键函数签名和状态流转即可。"

---

### 2. 配置/部署类问题

**标准问法：**
> "如果你记不住精确的配置项名称，可以说出配置结构、关键参数和它们的作用。更重要的是说明你怎么验证配置是否生效。"

**可追加：**
> "如果配置有问题，你会怎么排查？"

**示例：**
> "请口述 Celery 任务配置中你最关注的几个参数。不需要背命令，说出参数名和大致作用即可。"

---

### 3. SQL/数据库类问题

**标准问法：**
> "请说明你的 SQL 设计思路，写出表结构或关键查询的逻辑即可。不需要写出完整 SQL，但要说明索引设计考虑。"

**可追加：**
> "如果这个查询在大数据量下变慢，你会怎么优化？"

**示例：**
> "设计一个存储 Agent 执行步骤的表结构。口述字段设计和索引思路即可。"

---

### 4. 系统架构类问题

**标准问法：**
> "请画出或口述这个系统的核心组件和数据流。不要求细节完善，但要说清楚各组件的职责和边界。"

**可追加：**
> "如果 [某指标] 需要提升10倍，你的架构需要怎么调整？"

**示例：**
> "口述一个分布式采集系统的核心组件。包括调度、采集、去重、存储各层。"

---

### 5. 排障场景类问题

**标准问法：**
> "如果这是线上系统，请先说你的排查顺序，再说你会查看的日志、指标、链路和关键命令。"

**可追加：**
> "你如何快速判断是单机问题还是系统性问题？"

**示例：**
> "如果采集成功率突然从 99% 降到 80%，你的排查顺序是什么？"

---

### 6. 第三方服务/模型类问题

**标准问法：**
> "如果涉及第三方模型或服务，不要求你记住精确参数，但要说明设计思路和关键风险点。"

**可追加：**
> "如果这个服务突然不可用，你的降级策略是什么？"

**示例：**
> "你接了多个大模型（deepseek、chatgpt、Claude），不同模型共存时怎么做统一抽象？"

---

## 禁止的问法

线上面试中，避免以下问法：

| 禁止问法 | 问题 | 替代问法 |
|----------|------|----------|
| "请现场写出完整可运行的代码" | 无法验证环境，浪费时间 | "口述实现思路，写核心伪代码" |
| "请背出这个命令的完整参数" | 考察记忆而非理解 | "说明命令的关键参数和验证方式" |
| "请现场调试这段代码" | 环境不可控 | "分析这段代码可能的问题" |
| "请写出完整的 Docker Compose 文件" | 过于冗长 | "口述关键服务、依赖关系和配置要点" |

## 追问策略（线上面试专用）

### 验证"真做过"的追问

线上面试无法看代码仓库，但可以通过追问验证真实性：

| 追问类型 | 示例 |
|----------|------|
| **坑点追问** | "这个项目遇到过什么坑？你是怎么发现的？" |
| **量化追问** | "QPS 是多少？数据量多大？延迟多少？" |
| **决策追问** | "为什么选 A 方案不选 B？" |
| **边界追问** | "如果请求量翻10倍，这个设计会有什么问题？" |
| **回滚追问** | "如果上线后发现有问题，你的回滚方案是什么？" |

### 深挖追问

当候选人回答较浅时：

| 情况 | 追问 |
|------|------|
| 只说概念 | "你在实际项目中是怎么用到这个的？" |
| 只说结果 | "能具体说说你是怎么实现的吗？" |
| 只说"我们团队" | "你自己具体负责哪一部分？" |
| 回答模糊 | "能给一个具体的例子吗？" |

## 线上面试节奏建议

### 时间分配

| 阶段 | 时长 | 内容 | 注意事项 |
|------|------|------|----------|
| 开场 | 2-3分钟 | 自我介绍、确认身份、说明流程 | 建立信任，缓解紧张 |
| 热身 | 5分钟 | 基础问题、经历确认 | 校准水平，观察表达 |
| 深挖 | 20-25分钟 | 项目深挖、技术问题 | 核心考察阶段 |
| 开放 | 5-10分钟 | 架构、协作、开放题 | 判断 senior 程度 |
| 收尾 | 3-5分钟 | 候选人提问、后续说明 | 观察关注点 |

### 节奏控制

- **单题时长**：简单题 2-3 分钟，深挖题 5-8 分钟
- **追问次数**：每题至少 1 次追问，重点题可 3-5 次
- **切换时机**：如果候选人对某问题完全答不上，不要纠缠，快速切换
- **深挖时机**：如果候选人对某项目特别熟，可连续追问 4-6 题

## 技术问题示例（线上问法版）

### Python 基础

> "请解释 Python 的 GIL，它在你实际工作中造成过什么影响？不要求精确的底层实现，但要说明在什么场景下会成为瓶颈。"

### 数据库

> "如果 MySQL 查询变慢，你的排查顺序是什么？请说明你会看的日志、指标和执行计划。"

### Redis

> "Redis 除了缓存，在你的项目中还承担过什么角色？请举例说明。"

### Elasticsearch

> "口述一下 ES 的 text 和 keyword 字段的区别，以及你在什么场景下会选择哪种？"

### 架构设计

> "如果让你设计一个高并发接口的限流策略，你会怎么设计？口述关键思路和需要考虑的因素即可。"

### 分布式系统

> "在 DRF + Celery + ES + Redis 这种组合里，最容易出现的一致性问题是什么？你怎么处理？"

### AI/Agent 平台

> "多 Agent 系统里如何避免死循环？口述你的控制策略和关键判断条件。"

### 监控告警

> "如果让你给一个采集系统设计关键监控指标，你会优先看哪几个？为什么？"

## 候选人反问阶段

线上面试最后通常有候选人提问时间，可以观察候选人的关注点：

| 候选人问题 | 可能的信号 |
|-----------|-----------|
| 问技术栈、架构、技术债 | 关注技术成长 |
| 问团队规模、协作方式 | 关注工作环境 |
| 问业务方向、产品规划 | 关注业务价值 |
| 问加班、压力、出差 | 关注工作生活平衡 |
| 问薪资、晋升 | 关注职业发展 |
| 几乎不提问 | 可能兴趣不大 或 准备不足 |

## 常见问题处理

### Q: 候选人网络卡顿怎么办？
A: 先确认是否影响回答质量。如果是短暂卡顿，让候选人重复关键部分；如果是持续问题，建议改期。

### Q: 候选人要求共享屏幕写代码怎么办？
A: 如果时间允许且环境可控，可以接受。但要提前说明"更看重思路而非能否运行"。

### Q: 候选人回答过于简短怎么办？
A: 使用追问引导展开："能具体说说吗？""举个例子？""为什么这样？"

### Q: 候选人回答跑题怎么办？
A: 礼貌打断："理解，那我们回到刚才的问题，关于 [核心点] 你怎么看？"

## 线上面试检查清单

**面试前：**
- [ ] 确认视频会议链接可用
- [ ] 准备好题库和追问
- [ ] 测试自己的音视频设备
- [ ] 关闭无关通知

**面试中：**
- [ ] 开场时确认候选人听得清楚
- [ ] 说明面试大致流程和时间
- [ ] 使用标准化问法
- [ ] 记录关键回答和信号

**面试后：**
- [ ] 在30分钟内完成结构化结论
- [ ] 记录亮点、风险点和证据
- [ ] 明确下一轮建议（如有）
